# BOOTSTRAP.md

Procedure for installing **plan_foundry** into a target repository via an in-session Claude Code agent.

This file is the canonical single-source-of-truth for first-contact installs. The user pastes the trigger phrase into a fresh Claude Code session on their target repo; the agent recognises the phrase, fetches this file (or follows its baked-in procedure), and runs the install.

## Trigger phrase

> Bootstrap plan_foundry from https://github.com/kccastillo/plan_foundry into this repo.

## What you (the agent) should do

You are running inside the user's target project (CWD is the project root). Your filesystem write surface is the target repo; network is available. Run these three commands in order. Each is single-line and safe.

```bash
git clone --depth=1 https://github.com/kccastillo/plan_foundry .plan-foundry-tmp
python3 .plan-foundry-tmp/.claude/skills/init-plan-foundry/lib/run_install.py
rm -rf .plan-foundry-tmp
```

After the third command, **tell the user to RESTART Claude Code** so the freshly-copied skills register with the harness. Until restart, slash commands like `/plan-foundry-sync` will not resolve.

## What `run_install.py` does

A single-file Python CLI that performs the nine-step install procedure non-interactively from the cloned bundle. It is exactly equivalent to running `/init-plan-foundry` inside an already-installed project. Steps:

1. Refuse if CWD is the bundle source itself (basename or origin-URL match).
2. Copy `.plan-foundry-tmp/.claude/{skills,agents,commands,hooks}` into `./.claude/`. Idempotent across four precursor states (absent / symlink / hand-copy / fresh).
3. Scaffold `Workbench/`, `Retired/`, current-month LOG.
4. Update `.gitignore`: add bundle-managed paths, `.plan-foundry-tmp/`, version pin.
5. Inline operating-rules into `CLAUDE.md` between sentinel markers.
6. Write `.claude/.plan-foundry-bundle-version` with the cloned bundle's sha/tag/timestamp.
7. Print "RESTART Claude Code".

If `run_install.py` fails, surface its stderr; the user can investigate before deleting `.plan-foundry-tmp/`.

## Pinning to a specific version

If the user wants a specific bundle version (a released tag rather than `main`), replace `--depth=1` with `--depth=1 --branch <tag>`. Example:

```bash
git clone --depth=1 --branch v0.5.0 https://github.com/kccastillo/plan_foundry .plan-foundry-tmp
```

## Recovery from a half-failed prior run

If `.plan-foundry-tmp/` already exists from a crashed prior run, remove it before cloning:

```bash
rm -rf .plan-foundry-tmp
```

(The `--depth=1` clone refuses to overwrite an existing directory; this is by design.)

## What lives where after install

- `.claude/{skills,agents,commands,hooks}/` — bundle code (gitignored; regenerated by `/plan-foundry-sync`).
- `.claude/.plan-foundry-bundle-version` — version pin (gitignored).
- `.claude/settings.local.json`, `.claude/plan-foundry.config`, project-local scripts — your content (tracked).
- `Workbench/` — your PLAN files, audit records (tracked).
- `Retired/` — closed-out artefacts (gitignored).
- `CLAUDE.md` — sentinel block contains plan_foundry's operating rules; rest is yours.

## Removal

`/plan-foundry-uninstall` (after install) cleanly removes everything plan_foundry added without touching your `Workbench/`, `Retired/`, or any project-local `.claude/` files.
